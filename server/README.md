# Wien server

Rust-бэкенд: `axum` + Tokio, `reqwest`, `eventsource-stream`, OpenAPI через
`utoipa` и встроенный Swagger UI. `/v1/generate` делает один вызов модели,
а `/v1/assist` выполняет ограниченный цикл инструментов Strudel RAG.
История между пользовательскими запросами не сохраняется.

## Запуск

Нужны работающий Docker с Compose, `just` и ключ AI Tunnel в `AITUNNEL_KEY`. Команды выполняются из корня репозитория:

```sh
cp .env.example .env
# Заполни AITUNNEL_KEY и STRUDEL_RAG_BEARER_TOKEN в .env.
just run-server
# http://127.0.0.1:3001/docs/ — Swagger UI (ресурсы включены в бинарник)
# http://127.0.0.1:3001/openapi.json — генерируемый OpenAPI-контракт
# http://127.0.0.1:3001/health — проверка процесса, без обращения к модели
```

`just run-server` собирает образы и запускает `server` и RAG `skill` с общими логами.
Ctrl+C останавливает оба сервиса. RAG должен пройти healthcheck, но готовый индекс
для запуска не требуется. Подготовка индекса описана в [корневом README](../README.md).
Для `/v1/assist` нужен готовый индекс: при пустом корпусе запрос завершается
с `503 rag_not_ready` до обращения к модели. Compose передаёт серверу endpoint
`http://skill:50051` и bearer token. При запуске через Cargo задай
`STRUDEL_RAG_ENDPOINT` (по умолчанию `http://127.0.0.1:50051`) и
`STRUDEL_RAG_BEARER_TOKEN` в окружении; Cargo сам `.env` не загружает.

Порт хоста можно изменить: `WIEN_SERVER_PORT=3002 just run-server`.
Compose публикует его только на `127.0.0.1`; внутри контейнера сервер слушает
`0.0.0.0:3001`. При запуске без Docker адрес по умолчанию — `127.0.0.1`,
переопределяется через `WIEN_SERVER_HOST`. По умолчанию API принимает только локальные запросы.
Настройки CORS не открыты сторонним сайтам; ручка также проверяет Host и Origin.
Electron-клиент вызывает её из main process через ограниченный IPC; renderer не
получает credentials и не обращается к провайдеру напрямую.

## Конфигурация

Провайдер выбирается сервером при старте из `server/config.toml`:

```toml
provider = "aitunnel"

[generation]
model = "gpt-6-luna"
reasoning_effort = "low"
```

Compose подключает `server/config.toml` только для чтения в `/app/config.toml`.
Другой TOML-файл на хосте можно указать через
`WIEN_SERVER_CONFIG=/absolute/path/config.toml just run-server`.
Для изменения настройки нужен перезапуск сервера. Отсутствующий файл, некорректный TOML,
неизвестный провайдер или лишние поля останавливают запуск без fallback.
`generation.model` и `generation.reasoning_effort` задают общие настройки
для `/v1/generate` и `/v1/assist` (по умолчанию `gpt-6-luna` и `low`).
Необязательное `generation.instructions` задаёт системные инструкции только для
`/v1/generate`; редакторский ассистент использует свой основной промпт. В этом конфиге нет токенов: AI Tunnel читает `AITUNNEL_KEY`
из окружения при старте. Генерация и embeddings используют один ключ.

HTTP-клиент не выбирает и не настраивает провайдера. Поля `provider` нет ни в запросе,
ни в ответе, ни в OpenAPI-схемах; попытка передать его в запросе возвращает 400.

## Запрос

```sh
curl --fail-with-body http://127.0.0.1:3001/v1/generate \
  -H 'Content-Type: application/json' \
  -d '{
    "text": "Предложи короткий басовый паттерн для Strudel. Верни только код."
  }'
```

В запросе разрешён только обязательный `text`. Модель, reasoning и системные
инструкции задаются конфигом сервера; поля `options`, `model`, `reasoning_effort`
и `instructions` в HTTP-запросе отклоняются с 400. Поддерживаемые уровни reasoning
зависят от выбранной модели. После изменения конфига перезапусти сервер.

HTTP-запрос ждёт завершения и возвращает один JSON:

```json
{
  "id": "response-id",
  "model": "gpt-6-luna",
  "text": "note(\"<a1 f1 c2 g1>\").s(\"sawtooth\").lpf(650)",
  "usage": { "input_tokens": 30, "output_tokens": 24, "total_tokens": 54 }
}
```

`usage` может быть `null`. AI Tunnel использует нестриминговый Responses API и принимает только завершённый
ответ. Codex по-прежнему читает SSE до `response.completed`. Оборванный поток и `response.incomplete` не считаются
успехом. Таймаут — 120 секунд; лимиты — 256 KiB JSON-запроса, 128 KiB текста/инструкций
и 8 MiB ответа провайдера. Автоматических повторов запросов нет.

Ошибки имеют вид `{"code":"provider_timeout","message":"…"}`:
400 — некорректный ввод; 403 — не локальный Host/Origin;
413 — большой запрос; 429 — лимит провайдера; 502 — сбой/неполный ответ провайдера;
503 — неверные credentials провайдера; 504 — таймаут. Сырые ошибки upstream не возвращаются.

## Ассистент редактора

Инфраструктура обоих сервисов описана в [корневом README](../README.md#проверки-и-ci).
Общий пакет `rag-protocol` содержит gRPC-типы, `service-runtime` — JSON-логи в stderr
(`RUST_LOG`) и graceful shutdown. `/health` проверяет liveness; `/ready` проверяет
готовность корпуса RAG без вызова модели или embeddings.

`POST /v1/assist` принимает один запрос без истории:

```json
{
  "prompt": "Сделай бас мягче",
  "file": {
    "path": "first-light.strudel",
    "content": "note('a1').s('sawtooth').gain(0.2)",
    "cursor": { "anchor": 0, "head": 10 }
  }
}
```

`anchor` и `head` — смещения UTF-16 с нуля, как в CodeMirror/JavaScript;
равные значения означают курсор без выделения. Выделение — контекст, а не граница
правок. Путь относительный и служит только контекстом: сервер не читает и не пишет
пользовательские файлы. Лимит промпта — 16 KiB, кода — 128 KiB.

Перед вызовом модели сервер вычисляет `editor_context`: точный текст выделения,
его начало/конец (строки и UTF-16 колонки с единицы), позицию курсора и текст его
строки. Модели не нужно отсчитывать символы. Поддерживаются обратное выделение,
Unicode и многострочные фрагменты; смещения внутри surrogate pair отклоняются.

Сервер добавляет [мастер-промпт](prompts/assistant.md), музыкальный
[скилл](../skill/skills/strudel-rag/SKILL.md) и [адаптер](prompts/rag.md).
Контракт редактора имеет приоритет над общими рекомендациями скилла: отвечать
кратко и возвращать строгий JSON `{"message":"…","code":"полный новый файл"}`.
Для ответа без редактирования `code` равен `null`. Невалидный или слишком большой
ответ модели отклоняется с 502. Промпты и 20 жанровых гайдов встроены в бинарник;
после их изменения перезапусти `just run-server` для пересборки.

Перед первым шагом модели сервер вызывает `GetCorpusInfo`. Затем модель выбирает:

- `strudel_rag_search` — сфокусированный поиск с intent и фильтрами, top_k от 1 до 10;
- `strudel_rag_get_document` — чтение документа/чанка, включая полный parent;
- `strudel_rag_get_corpus_info` — сведения о корпусе и его пробелах;
- `get_genre_guide` — один из встроенных жанровых гайдов по фиксированному имени.

Гайды не являются частью RAG-индекса. Сервер не запускает shell/CLI и не читает
произвольные пути от модели. Поиск и чтение используют gRPC-клиент, сгенерированный
из `skill/proto/strudel/rag/v1/rag.proto`; индексирующий код в сервер не включён.
Источники, ревизии и verification status передаются модели вместе с текстом.
Извлечённые материалы считаются данными, а не инструкциями.

Лимиты одного `/v1/assist`: 120 секунд на весь цикл (включая RAG), 8 шагов модели,
12 модельных вызовов инструментов, 15 секунд на RPC, 64 KiB на результат инструмента,
512 KiB на сериализованную историю. Слишком большой результат не обрезается:
модель получает ошибку с предложением сузить запрос. Ошибочные аргументы и ненайденный
документ допускают исправление в пределах бюджета. Сбой RAG, авторизации или embeddings
останавливает запрос без изменения файла; raw ошибки upstream не возвращаются.
`rag_not_ready`, `rag_unavailable`, `rag_unauthorized`, `rag_timeout` дают 503;
`assistant_limit` — 502. Fixtures всегда помечаются как тестовые данные.

Один процесс сервера выполняет до 4 запросов `/v1/assist` одновременно. Остальные
сразу получают `429 assistant_busy` с `Retry-After: 2`, до любых вызовов RAG и модели.
Серверной очереди нет; слот освобождается при завершении, ошибке, таймауте или
отмене обработчика. `/health` и `/v1/generate` этим лимитом не ограничиваются.

Клиент повторяет только `429 assistant_busy`: максимум 3 повтора после первой
попытки, с задержками 2, 4 и 8 секунд плюс случайные 0–499 мс. Если `Retry-After`
в секундах больше текущей задержки, клиент ждёт указанный срок; значение больше
30 секунд завершает запрос сообщением о занятости. Каждая попытка отправляет
исходный снимок файла. Отмена прерывает ожидание и запрещает дальнейшие повторы.
Остальные ошибки, включая лимит провайдера, ошибки RAG и сетевые таймауты, не
повторяются. Клиентский таймаут 125 секунд применяется к каждой HTTP-попытке.

Внутри одного запроса сохраняются завершённые reasoning/function-call items и
`function_call_output` с исходным `call_id`, при `store:false` — также encrypted
reasoning. Формат следует [Responses function calling](https://developers.openai.com/api/docs/guides/function-calling).
История живёт только до завершения текущего HTTP-запроса.

Клиент по `⌘,` открывает поповер с автофокусом и показывает только последний ответ.
Новый запрос содержит актуальный файл, но не предыдущий диалог. Код проходит
проверку синтаксиса и применяется одной отменяемой правкой; обычное автосохранение
продолжает работать. Если файл изменился, ответ не заменяет свежий код.
Закрытие поповера, переключение файла или отмена прерывают клиентский HTTP-запрос
и игнорируют поздний результат; уже начавшийся запрос провайдера может завершиться.
Модель не запускает музыку. Новые файлы ассистент пока не создаёт.

Если используешь другой порт, передай одинаковый `WIEN_SERVER_PORT` обеим командам
запуска. Сгенерированный пример запроса — `http/PostAssist.http`.

## AI Tunnel и удалённый API

`src/providers/aitunnel/` обращается только к `https://api.aitunnel.ru/v1/responses`.
Ключ берётся из `AITUNNEL_KEY`; fallback на другие сервисы отсутствует.
Лимит — 4096 выходных токенов на шаг, 8 MiB ответа и 120 секунд;
автоматических повторов генерации нет, чтобы не дублировать платные запросы.
История инструментов и reasoning сохраняется между шагами в пределах одного запроса.
HTTP 401/403 становится `provider_auth_required`, 402/429 — `provider_rate_limited`.
Сырые ошибки провайдера и credentials клиенту не возвращаются.
Если у ключа включён IP allowlist, исходящий IP сервера должен быть разрешён
в AI Tunnel; иначе провайдер вернёт 403 даже с правильным ключом.

В текущем деплое на VPS публичная генерация `/v1/*` отключена в Nginx.
Аккаунты и регистрация будут отдельным шагом. `/health`, `/ready` и документация
доступны по домену; приложение по-прежнему проверяет локальный Host/Origin.
Swagger использует текущий origin. После смены `AITUNNEL_KEY` пересоздай контейнеры,
чтобы обновить окружение. Ключ не передаётся клиенту.

## Опциональный локальный Codex

Адаптер `src/providers/codex/` сохранён. Для него поставь `provider = "codex"`
в `server/config.toml` и выбери доступную аккаунту модель. RAG всё равно использует
AI Tunnel. `just run-server` всегда добавляет `compose.codex.yaml` последним к
списку `COMPOSE_FILE` из окружения или `.env` (по умолчанию `compose.yaml`).
Дополнительные файлы, например `compose.ca.yaml`, сохраняются. Локальный файл
авторизации Codex монтируется при любом выбранном адаптере и должен существовать.
Команда `docker compose up` без этой локальной обёртки работает как прежде.

Override монтирует файл read-only в `/run/wien/auth.json`. Приоритет пути:
`WIEN_CODEX_AUTH_FILE`, затем `$CODEX_HOME/auth.json`, затем `$HOME/.codex/auth.json`.
Нужны `tokens.access_token` и `tokens.account_id`; API key login и системный keychain
не поддерживаются. Codex владеет обновлением токенов. После замены файла пересоздай
контейнер сервера, поскольку bind mount может видеть прежний inode.
Сервер читает credentials при запросе, не обновляет их и не запускает Codex CLI.
Это dev-адаптер внутреннего Codex HTTP-протокола, а не основной провайдер деплоя.

## Контракт провайдеров

`src/providers/mod.rs` содержит `Provider::send(text, options)` для обычного текста
и `Provider::turn(TurnRequest)` для одного шага с инструментами, общие настройки,
результат, ошибки и `ProviderKind` с фабрикой провайдеров.
Реализации лежат в `src/providers/<name>/`. При старте конфиг выбирает одну реализацию,
HTTP-слой получает готовый `Arc<dyn Provider>`. Новый провайдер реализует trait и
добавляется в `ProviderKind::build()`; ручку менять не нужно. Цикл и исполнение
инструментов находятся в `assistant`, сетевой RAG-клиент — в `rag`.

## Разработка и проверки

```sh
just generate       # OpenAPI + запросы server/http/*.http, без запуска сервера
just test           # клиент + rustfmt --check + Clippy + Rust-тесты
docker compose build server
# Альтернативный запуск из корня без Docker (Rust из rust-toolchain.toml):
cargo run -p wien-server --locked
cargo fmt --all
cargo test -p wien-server --locked
```

Cargo.lock хранится в корне общего workspace и используется в CI. Тесты используют только временные
файлы с искусственными credentials и локальный wiremock; настоящие токены и подписка
для `just test`/CI не нужны. HTTP-тесты проверяют маршрутизацию, контракт, ошибки,
лимиты и доступ к Swagger; тесты провайдера — протокол, завершение SSE, таймауты,
редиректы и перечитывание авторизации.

## Запросы из VS Code

1. Выполни `just generate` из корня репозитория.
2. Установи рекомендованное расширение **REST Client** (`humao.rest-client`).
3. Запусти `just run-server`, открой `server/http/GetHealth.http` или
   `server/http/PostGenerate.http` и нажми **Send Request** над запросом.

Генерация экспортирует тот же контракт, что `/openapi.json`, в `server/openapi.json`,
затем запускает [httpgenerator](https://github.com/christianhelle/httpgenerator)
**1.1.0**. При первом запуске Cargo устанавливает эту версию с `--locked` в
игнорируемый `target/tools`; для установки нужен интернет. Последующие запуски
используют локальный бинарник. Сам Wien, его конфиг и credentials провайдеров для генерации
не нужны. Генератор запускается с отключённой телеметрией (`--no-logging`).

У версии 1.1.0 есть два ограничения: встроенная валидация не поддерживает OpenAPI 3.1,
а генерация тела не учитывает `example`. Поэтому используется `--skip-validation`,
а небольшой Rust-шаг подставляет JSON-тело из `requestBody.content.application/json.example`
в уже созданный `.http`. Маршруты, заголовки и имена файлов генерирует библиотека.
Для новых JSON-ручек добавляй полноценный пример в аннотацию `utoipa::path`.
Тест проверяет, что сгенерированное тело совпадает с примером и принимается обработчиком.

`server/openapi.json` и сгенерированные `.http` храним в Git. После изменения API запускай
`just generate`; CI проверяет их актуальность командой
`bash server/scripts/generate-http.sh --check` без изменения файлов.
Генерация обновляет помеченные файлы и удаляет устаревшие помеченные запросы.
Рукописные `.http` сохраняются; при конфликте имён команда завершается ошибкой.
Для экспериментов скопируй запрос в файл с другим именем и убери первую строку
`# Generated by just generate...`. В своей копии можно менять `@baseUrl`, модель и текст.

В VS Code установленный `rust-analyzer` форматирует Rust при сохранении.
Default build task **Wien: Run** (`⌘⇧B`) запускает клиент и сервер параллельно
в двух терминалах одной split-группы. Задача сервера запускает Compose;
после изменения Rust-кода её нужно перезапустить для пересборки образа.

Интеграционный тест ассистента поднимает настоящий локальный gRPC-транспорт с
тестовыми документами и HTTP-заглушку модели: проверяет guide → search → parent →
ответ, передачу metadata, ревизий и encrypted reasoning. Это проверка протокола,
не оценка реального корпуса или качества музыкальных ответов.
